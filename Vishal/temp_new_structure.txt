Brand AI Readiness AuditProject Architecture & Implementation Specification
Adobe University Hackathon 2026 — Round 3Agent Skill Marketplace
Purpose: a complete implementation-ready architecture for a provider-neutral website audit marketplace covering off-site AI discoverability and on-site engagement.
1. Core Objective
Build one Agent Skill Marketplace package with exactly one designated entrypoint and multiple focused specialist skills. The entrypoint receives a website audit request and produces one structured audit report.
Off-site AI discoverability: why AI systems may fail to find, access, read, understand, verify, or confidently use/cite site information.
On-site engagement: why visitors who arrive may fail to understand the site, maintain context, find useful information, or continue to a useful next step.

4. Main Agent / Entrypoint
audit-orchestrator
Validate and normalize the target URL.
Apply read-only and robots policies.
Coordinate shared evidence collection.
Run crawl, semantic, trust and engagement analyses.
Aggregate and deduplicate findings.
Use AI reasoning where interpretation is required.
Filter false positives.
Assign evidence-based severity.
Generate mechanism-specific prioritized actions.
Emit one final report using the required schema.
5. Shared Evidence Collector
core evidence layer
HTTP status, redirects, HTTPS behavior and response metadata.
robots.txt and sitemap information.
Bounded crawl URLs and depth.
Raw/initial HTML.
Selective rendered DOM.
Visible text, headings, metadata and Open Graph data.
JSON-LD/structured data.
Internal links, navigation, breadcrumbs and calls to action.
Freshness/date signals and repeated factual claims.
6. Deterministic Checks
objective observations
HTTP/access status.
robots restrictions.
sitemap discoverability.
raw versus rendered content.
structured-data presence/parseability/consistency.
entity names and identity signals.
navigation and next-step signals.
freshness and repeated-claim signals.
7. Crawl & Render Skill
crawl-render-audit
Question: Can machines reach and read the site?
Check HTTP/HTTPS, redirects, errors, robots and timeouts.
Check sitemap, internal links, crawl depth and important URLs.
Inspect useful machine-readable HTML text.
Compare initial HTML with rendered DOM.
Determine whether rendered-only content is important factual/core content rather than UI.
8. Semantic & Entity Skill
semantic-entity-audit
Question: Can an AI understand what the site, organization, product or service is?
Inspect titles, headings, explicit facts and marketing-vs-factual language.
Inspect Organization/Product/Service structured data.
Compare visible content with JSON-LD.
Detect ambiguity or inconsistent identity signals.
Do not treat missing structured data alone as a severe defect.
9. Freshness & Corroboration Skill
freshness-corroboration
Question: Can important information be verified and trusted?
Detect date/freshness signals.
Identify potentially stale important claims.
Compare repeated claims across pages.
Detect contradictions/inconsistent descriptions.
Track corroboration signals where available.
Phrase conflicts as claims requiring investigation rather than automatically declaring one source false.
10. Engagement Skill
engagement-audit
Question: Once a visitor arrives, can they understand, navigate and continue?
Orientation: what the site/page is, what it offers and who it serves.
Context retention through labels, breadcrumbs and coherent destinations.
Navigation to relevant information.
Useful next steps such as documentation, pricing, contact, demo, purchase or related content.
Detect dead ends.
Tie findings to observable page structure rather than purely subjective judgments.
11. Evidence Aggregation
Combine specialist outputs into a common candidate-finding set while preserving source provenance. Merge findings that describe the same underlying mechanism and remove duplicates.
Example: a crawl finding that core product content is absent from initial HTML and a semantic finding that product information is difficult to extract may be one rendering/readability finding.
12. AI Reasoning Layer
Interpret whether a detected condition materially affects discoverability or engagement.
Distinguish important factual content from cookie banners, navigation, footer text and other UI.
Connect multiple signals into one mechanism-based finding.
Explain why the evidence matters.
Generate precise recommendations.
Use collected evidence only; never invent page facts.
13. False-Positive Filtering
Is there sufficient evidence?
Does the underlying problem actually exist?
Does it materially affect discoverability, understanding, verification or engagement?
Could the condition be normal/benign?
Is it already covered by another finding?
Is severity proportional to evidence and impact?
Core principle: do not turn a missing feature into a problem unless evidence shows that it contributes to the underlying audited issue.
14. Severity Assignment
Severity
Meaning
CRITICAL
Major issue substantially preventing important information from being discovered, accessed, read, understood or used, or a severe engagement blocker.
HIGH
Significant issue likely to materially reduce AI discoverability or visitor continuation.
MEDIUM
Meaningful weakness reducing clarity, verification, navigation or engagement but not blocking.
LOW
Minor improvement opportunity with limited impact.
15. Mechanism-Based Recommendations
Each action must map directly to the mechanism of the finding.
Bad: “Improve SEO.”
Good: “Expose the core product description, key features and essential facts in initial/server-rendered HTML while retaining JavaScript for interactive enhancements.”
summary
priority
16. Proactive Recommendations
Include relevant proactive improvements even when no severe defect is found, without generic checklist padding.
Create or improve an authoritative organization description.
Make important product/service facts explicit and extractable.
Improve contextual navigation between related content.
Strengthen useful next-step pathways.

18. Final Report Schema
{  "site": "https://example.com",  "audited_at": "2026-09-10T...",  "summary": {    "total_findings": 5,    "critical": 0,    "high": 2,    "medium": 3  },  "findings": [    {      "id": "CRAWL-001",      "title": "Core product content is not available in initial HTML",      "severity": "high",      "evidence": "...",      "suggested_action": {        "summary": "Expose core product information in initial/server-rendered HTML.",        "priority": "high"      }    }  ]}
Optional useful fields: category, area, confidence, why_it_matters, source URLs, observations and evidence provenance.
19. Runtime & Safety
Target under five minutes for a typical website.
Read-only analysis only.
Respect robots.txt.
No authentication or private-area access.
No form submission or site modification.
No destructive actions.
Avoid aggressive/rate-abusing crawling.
Provider-neutral and self-contained.
Prefer bounded crawling and selective rendering.

22. Implementation Principles
Build patterns, not site-specific hacks.
Evidence first; reasoning second.
Do not automatically treat missing SEO features as defects.
Every finding must have concrete evidence.
Recommendations must match the mechanism.
Keep specialist responsibilities genuinely distinct.
Use shared evidence to avoid repeated crawling.
Make severity explainable and rule-driven.
Keep SKILL.md concise; put detailed guidance in references and executable checks in scripts.
Preserve read-only, safe and portable behavior.

24. Final Mental Model
The strongest design is one composed audit agent with specialized skills, shared evidence collection, deterministic checks, evidence-based AI reasoning, strict false-positive control, explainable severity and mechanism-based recommendations.
OBSERVE → ANALYZE → CORRELATE → REASON → FILTER → PRIORITIZE → RECOMMEND → REPORT
